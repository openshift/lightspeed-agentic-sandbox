# Agentic Tool-Output Redaction [PLANNED: OLS-3939]

This is the **lightspeed-agentic-sandbox** runtime contract for the shared policy in the parent `openshift/ols/.ai/spec/what/tool-output-redaction.md` ([proposed parent PR #126](https://github.com/openshift/ols/pull/126)). It is not implemented or committed to an OLS 2.0 release. The parent spec owns categories, placeholders, default-on policy, one-pass match semantics, logging metadata and verification corpus; this file specifies sandbox interception and handoff only. Existing inspection and native evidence contracts in `what/provider-contract.md`, `what/audit-logging.md` and `what/data-collection.md` continue to govern their respective boundaries.

## DeepAgents boundary

1. All implemented DeepAgents routes MUST apply one effective tool-output policy across successful and handled-error results from MCP tools, native shell/`oc`/`kubectl` execution and skill-triggered tools. An exemption from injection inspection for trusted skill-source reads is **not** an exemption from redaction if the content enters model context. Do not implement provider-specific bypasses or a fallback to unguarded legacy harnesses.
2. At sandbox setup, compile the effective validated named-alternative matcher once per configuration revision and reuse it throughout the run. Each effective tool reply gets one substitution pass that returns sanitized text, `redacted: bool`, `redacted_count: int` and category counts; replacements are visible named placeholders. The built-ins do not redact standalone IP addresses or CIDR ranges. No per-tool compilation or second scan for counts. Invalid policy fails setup; unexpected runtime redaction failure fails closed before any model/classifier/UI content is released.
3. Redact model-visible successes and tool-generated error text after existing SDK/tool output limits and before the isolated injection classifier and main-agent reinjection. If inspection is enabled, its classifier sees sanitized text and its existing pass/fail behavior is unchanged; if disabled, redaction still applies. Apply the same boundary to offloaded read/search/preview results and all other effective content returned to the model. On inspection rejection, emit no normalized result or partial user reply.

## Raw evidence versus normalized events

4. Existing native source spans capture a successful callback's **raw** result at tool completion, independently of later redaction or inspection; content-enabled compliance copies may retain it. OLS-3939 does **not** alter full-fidelity source audit/trace evidence or its access/retention policy. Normalized `ToolResultEvent` and user-visible Result CR/replay projections, by contrast, MUST contain sanitized tool content and per-reply metadata only after admission. Never expose raw payloads via new developer logs, normalized event content, a UI attachment, error details, copy or download action. Retain SDK-reported real tool-call IDs; do not fabricate one for missing/ambiguous IDs.
5. The agentic-operator MUST supply the same validated effective `OLSConfig.toolOutputRedaction` policy as Classic to the sandbox. The sandbox/agentic-operator MUST hand each actual admitted tool reply's sanitized projection, boolean/count and real call ID (when available) to the Agentic UI in a **typed structured** record with run/phase correlation. A final Result/status representation can carry persistent records; live display requires its own explicitly designed transport. There is no existing sandbox-to-console HTTP SSE to reuse, and the console MUST NOT infer flags by parsing pod-log prose. The UI renders a clear accessible "Sensitive values redacted" indicator next to the sanitized reply when true; when false, show only the sanitized reply and do not imply complete DLP. Do not render raw tool payload in the existing live pod-log viewer or publish a reply without the corresponding safe metadata.

## Logging, failure and verification

6. For a result with matches, emit one metadata-only record after interception with controlled tool identifier, result/error kind, counts and category names; emit no per-result redaction record for zero matches. At load/change log safe policy state once, warning once for explicit disablement; record only a controlled error code on invalid configuration or matcher failure, never a snippet/value/hash. Validate `gen_ai.tool.pii_redacted` against the deployed OTel semantics or use a documented namespaced attribute instead. Native tool source spans are not replaced or duplicated by this metadata record.
7. Verify the parent single-result ConfigMap corpus (ten matches, two phone numbers, unchanged IPv4/IPv6 CIDRs) against all supported DeepAgents routes with both inspection states. Include tool errors, offloaded reads, concurrent results, missing call IDs, failure, normalized event suppression on rejection, metadata handoff, UI replay and raw source spans. Assert no unredacted result reaches classifier/main model, normalized user-facing result or new developer logs. Tests must distinguish live provider acceptance from offline mocks and verify no false redaction for benign Kubernetes output.
